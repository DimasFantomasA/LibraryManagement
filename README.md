# LibraryManagement — система управления библиотекой

Курсовой проект по базам данных. Приложение предназначено для автоматизации учёта книг, читателей, выдачи и возврата книг, пожертвований и формирования отчётов.

## Технологии

- C# и Windows Forms
- .NET
- PostgreSQL
- Npgsql
- Visual Studio 2022
- pgAdmin 4
- Git и GitHub

## Функциональные возможности

### Справочники

- Книги: просмотр, добавление, изменение и удаление записей.
- Читатели: управление сведениями о читателях.
- Типы книг: управление категориями, сроками выдачи и ежедневными штрафами.

### Журналы

- Выдача и возврат книг с проверкой доступности экземпляров.
- Учёт пожертвований и изменение количества экземпляров.

### Отчёты

- Самые популярные книги — рейтинг по количеству выдач.
- Штрафы за просрочку — расчёт суммы штрафа по сроку возврата и дневной ставке.
- Экспорт обоих отчётов в TXT с кодировкой UTF-8.

## Авторизация и права доступа

| Операция | Администратор (`admin`) | Библиотекарь (`librarian`) |
|---|---|---|
| Просмотр данных | Да | Да |
| Добавление записей | Да | Да |
| Изменение записей | Да | Да |
| Удаление записей | Да | Нет |
| Выдача и возврат книг | Да | Да |
| Формирование и экспорт отчётов | Да | Да |

Пароли хранятся в виде производных значений PBKDF2 с индивидуальной солью. Роль авторизованного пользователя хранится в `UserSession`. Ограничение удаления реализовано на уровне интерфейса и обработчиков приложения, а не отдельных ролей PostgreSQL.

## Структура базы данных

| Таблица | Назначение |
|---|---|
| `books` | Книги и количество экземпляров |
| `book_types` | Типы книг, сроки выдачи и штрафы |
| `clients` | Сведения о читателях |
| `journal` | История выдачи и возврата |
| `donations` | Учёт пожертвований |
| `app_users` | Учётные записи, роли и параметры проверки паролей |

Для работы с данными используются параметризованные SQL-запросы, соединения таблиц, агрегатные и оконные функции, транзакции и триггеры PostgreSQL.

## Установка и запуск

### 1. Подготовка среды

Установите PostgreSQL и Visual Studio 2022 с компонентом «Разработка классических приложений .NET». Версию .NET SDK выбирайте согласно `TargetFramework` в `LibraryManagement.csproj`.

### 2. Получение исходного кода

Скачайте репозиторий через **Code → Download ZIP** либо склонируйте его командой `git clone`, используя HTTPS-адрес репозитория.

### 3. Восстановление базы данных

Создайте пустую базу PostgreSQL, например `library`. Выполните SQL-скрипт `Database/library_schema.sql` с помощью `psql` (из корня репозитория):

```powershell
psql -h localhost -p 5432 -U postgres -d library -v ON_ERROR_STOP=1 -f Database/library_schema.sql
```

Если `psql` не найден, используйте полный путь к нему в папке `bin` установленного PostgreSQL. При восстановлении используйте совместимую версию PostgreSQL. Имя базы и пользователя в команде при необходимости измените.

Экспорт только структуры не содержит записей книг, читателей и пользователей. Для демонстрации потребуется добавить тестовые данные либо восстановить отдельно предоставленную полную резервную копию в пустую базу вместо выполнения скрипта структуры.

### 4. Настройка подключения

В папке проекта `LibraryManagement/` скопируйте `database.example.ini` в `database.ini`. Укажите фактические параметры PostgreSQL, сохранив формат и имена ключей исходного шаблона. Убедитесь, что `database.ini` копируется в выходную папку сборки и находится рядом с исполняемым файлом.

Не публикуйте файл с реальными паролями в GitHub.

### 5. Создание пользователей приложения

Для новой пустой базы необходимо создать две учётные записи в `app_users`: `admin` с ролью `administrator` и `librarian` с ролью `librarian`.

Для первоначальной регистрации используется предусмотренный проектом класс `UserSeeder` совместно с `PasswordHelper`. Создание пользователей должно выполняться с использованием локально заданных паролей и корректных параметров хеширования. Точный вызов метода следует сверить с сигнатурой в `UserSeeder.cs`. Не оставляйте реальные пароли в исходном коде и не выполняйте повторную инициализацию при каждом запуске.

Учётные записи приложения отличаются от пользователя сервера PostgreSQL, указанного в конфигурации подключения.

### 6. Запуск приложения

Откройте `LibraryManagement.sln` в Visual Studio, восстановите пакеты NuGet, выберите C#-проект `LibraryManagement` в качестве запускаемого и выполните сборку. Запустите приложение клавишей F5 и авторизуйтесь под одной из созданных учётных записей.
